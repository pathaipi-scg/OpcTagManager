## Startup Performance Regression and Fix

After adding multi-line isolation, scoped reconciliation initially
performed SQL operations sequentially per tag. With about 2,030 SB12
tags this caused roughly 12,000--14,000 Python-to-database execution
calls and startup could take 10--13+ minutes.

The scoped registry implementation was changed to bulk behavior: 1. Load
current-line TagMaster once. 2. Load current-line TagLevel once. 3.
Classify tags in memory. 4. Use batched `executemany`. 5. Use
`fast_executemany` where supported. 6. Preserve TagIds. 7. Mark
unchanged tags with current LastBrowseRunId. 8. Preserve valid
hierarchy. 9. Rebuild hierarchy only for
new/missing/duplicate/inconsistent cases. 10. Restrict all changes to
current `LineName`. 11. Preserve per-line locking and rollback behavior.
