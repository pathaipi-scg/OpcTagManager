## Architecture

- OPC Runtime Tree: SQL `TagMaster` data, with the existing runtime refresh workflow.
- Kepware Configuration Tree: live Kepware Configuration API v1.
- Kepware browsing: lazy-loaded by Channel, Device, and immediate Tag/Tag Group children, with a 30-second TTL cache.
- Kepware writes: controlled single-Tag creation with preview, duplicate detection, explicit Data Type/Scan Rate/Access, and returned-value verification.
- Create Like This: copies safe operational values from a selected Tag while requiring a new Name and Address.
- Tag Knowledge: stored beneath configured `KM_TAG_ROOT` only. OpcTagManager must never write to sibling Factory-KM roots.

## Phase 4.3 Tag Knowledge

- The directory is built from structured Channel, Device, recursive Tag Groups, and Tag Name. Display-path strings are not split to derive filesystem paths.
- The Tag is its own folder, for example `D:\KM\Vault\Tags\LP2\MIX\Cement_FML\`.
- Valid Windows components are preserved exactly. Traversal components are rejected; invalid characters and reserved Windows device names are deterministically encoded.
- Every canonical destination is verified beneath `KM_TAG_ROOT`.
- Version files use `<TagName>_YYYYMMDD_HHMMSS.md`; collisions receive a safe suffix and never overwrite a file.
- `knowledge.index.json` records the active filename, version, exact Kepware path, and update timestamp.
- Historical Markdown versions are preserved.
- Kepware Tag writes and KM Knowledge writes use independent safety gates.
- Image, document, and attachment support is not implemented.
