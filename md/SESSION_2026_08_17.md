## Phase 4.10 implementation handoff

Phase 4.10 - Canonical Integration Contracts is implemented and awaits review. The outward revision format is `v<active_version>:<active-version-sha256>`, derived from existing immutable Shared Resource metadata. Meaningful Supplier and EPT edits advance it; semantic no-ops do not. Contacts expose their owning Supplier revision rather than acquiring a separate registry.

New read-only integration surfaces are `GET /api/canonical/{canonical_id}` and `GET /api/opc-tags/search`. The canonical endpoint provides safe current state for Supplier, Contact, Equipment/Part, and Shared Resource identities. Tag search uses the existing runtime TagMaster source with parameterized, deterministic, bounded reads and does not call or mutate Kepware.

`POST /api/integration/resources` is the controlled multipart handoff for Factory-KM-created Manual, Drawing, Quotation, and General Document content. It requires declared SHA-256 and logical Factory-KM provenance, reuses exact-SHA idempotency and existing similarity decisions, remains protected by `KM_RESOURCE_WRITE_ENABLED`, and never accepts a physical path as cross-service identity. It does not create Suppliers/EPTs or relationships.

The future Factory-KM executor must preflight every reviewed canonical identity and treat `current canonical_revision != expected canonical_revision` as `CONFLICT`. No Factory-KM executor, relationship execution, live Resource/Vault write, Kepware mutation, authentication change, KMVaultManager change, commit, or push was performed in Phase 4.10.
